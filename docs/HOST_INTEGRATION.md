# Optional Host integration — DSH 0.2.1-alpha.1

This records the actual adapter in [host.ts](<../src/host.ts>) and its browser-safe [Remote contract](<../src/controls/remote-contract.ts>). It does not authorize profile activation, live GUI changes, installation/publication or model trials. The immutable Skill provider remains independent of this optional adapter.

## Composition, ownership and persistence

The mandatory mountHost(ctx, { createRuntime(ports) }) factory mounts real Cordis, ToolRuntime and Typert registrations. [RuntimeFacade / HostPorts](<../src/host.ts>) separate host facts from package-owned instruments/windows/resources/consumption. No fake default runtime, memory fallback or internal-instance monkeypatch exists.

Each authoritative aggregate owns a separately opened, single-table domain: controls, instrument records, windows, resources, policy grants and explicitly requested runtime units. The module-only openUnitStorage(suffix, parser) validates its suffix, reserves a records/state row and retains the domain for teardown. Models cannot name/open units. Same suffix and exact parser identity share one cached pending/open VersionedStorage handle throughout this mount; another parser is invalid-state before backend access. The cache also retains failed opens and the table-wide indeterminate-write latch, rather than reopening or inventing empty state. Pending opens are tracked through teardown. The sole generic cache cast is justified by that checked parser identity. Existing CAS adapters preserve uncertain-write latches. Failed persistence is not empty state; indeterminate outcomes require a fresh close/reopen and reconciliation. These domains are not a cross-domain/multi-process transaction.

Shutdown removes listener/tool/descriptor contributions, cancels mount lifetime, drains tracked Remote/tool/event work, disposes the runtime and closes domains. In-flight Remote methods receive carrier plus mount cancellation. The Cordis fiber ultimately removes its Service registration.

## Trusted callers and lineage

- Remote requires an actual ctx.invocation with peer.id equal to ctx.connection.operator.id. Arbitrary peers are not ACLs; the wire never supplies principals. This is a single-profile operator policy, not plugin-invented multi-user authentication.
- Agent identity is agent:<actual Agent.id>. It must match the exact live registry object and session.header.id. Instrument tools address that Agent's own Session; business assignments/coordinator roles remain runtime-authorized.
- Agent policy writes default denied. Only an authenticated operator persists/revokes an exact Session policy grant under its own CAS revision. There is no model self-grant tool. Host grant mutations require the private generic serializePolicyPermission callback capability and share the runtime policy-effect FIFO; no absent-method fallback bypasses that order. A queued revocation therefore precedes a later policy commit and its fresh authorization check. This grant neither widens file/approval permissions nor confers business coordination.
- Delegated identity requires trusted origin=subagent, parentSession and its supported native own descriptor or verified retained managed association. Missing child identity never promotes to owner. Ordinary forks get independent owner instances even when parentSession/isSeeded exists.
- Live descriptor reads use ownEvents(). Cold observations exclude inheritedEventCount before folding and always dispose the lease. One-shot setup can precede its first descriptor: runtime creation should leave this unconfirmed until the first admitted step, not reject native setup or manufacture an owner.
- Only root cwd selects an already registered WorkspaceId by exact canonical path. No createWorkspace, attachSession relocation or retained reassignment by path/title. Missing registration/directory makes verification false while original identity remains retained. Navigation membership is not ACL.

## Remote and model surface

Operator listWorkspaces also returns copied native workspace.sessionIds for same-page Session navigation. The shared row type permits omission for older fixtures, but the actual Host supplies it. The SDK field is a synchronous readonly, header-validated ordered projection (installed dsh-workspace/lib/types/types.d.ts:72–80). It is navigation, never delegation or ACL; listing does not observe/resume cold Sessions or create instrument instances.

The namespace is mattpocockControls. Methods: readPolicy(); savePolicy(intent, expectedRevision); listWorkspaces(); readSession(sessionId, signal?); applyInstrument(sessionId, command); applyTicketWindow(sessionId, command); resourceAction(sessionId, request); grantPolicy(sessionId, enabled, expectedRevision).

The readSession cancellation signal is a final Typert transport argument, never wire JSON; the descriptor declares cancellation.parameter=signal and Host combines carrier, supplied and mount signals. Host registration and Client $mount select the same exported REMOTE_CONTRIBUTION. Every codec is strict with explicit parse factories, not SRC-JSON fallback. TypertRemoteService supplies the explicit bindTypertRemote binding. Closed input parsers reject author/principal/execution-receipt claims and non-lossless JSON. The shared contract imports SDK types only, so no Host/Node runtime enters the browser.

The basic tools are mattpocock_controls, mattpocock_record, mattpocock_window and mattpocock_resource. Optional runtime-supplied execution/assignment methods receive generic wrappers under mattpocock_execute and mattpocock_assign. Host does not implement their scheduling/business semantics. Tool outputs are canonical JSON under actual schema/renderers.

executeNative nests actual ctx.tools.execute under original subagent/subagent_fork/send_message names with root identity, parent token, actual Agent and signal. It never aliases away original permissions or directly invokes another definition's body. Runtime private-capability composition may install synchronous monotonic guards: deny only, never force-allow. Program receipts are not model/Remote inputs.

## Source-only continuable creation and initial cwd authorization

The source adapter now offers optional program ports authorizeInitialChildCwd(exec, cwd), createContinuable(exec, { provider: spawn | fork, label, prompt, childId, cwd? }) and flushSession(sessionId, signal). They do not modify the installed SDK/Profile/GUI. The same-package compatible provider exposes initialCwdSupported through the actual native manager, and a host-native activation service exposes startActivation together with the session working-directory owner; the adapter reports support only when one of those two loaded public seams is actually present, never from a version string or a caller claim. A host service without either seam remains unsupported. Host startup separately inspects same-plugin next-boot assets and public Loader resolution, without SDK writes; readiness is never a current capability claim. Existing Release/current GUI installation is not changed by these source edits. Native inbox acceptance returns only childId/messageId; runtime must obtain an actual native flush checkpoint and independently verify matching child/parent/cwd facts before claiming a durable binding.

An explicit cwd follows authorization → durable intent → native effect: runtime calls authorizeInitialChildCwd and rechecks the actual parent before any delegation journal/binding intent, then records intent and calls createContinuable. The trusted preflight returns void and performs no native creation or durable intent writes; it is not a reusable permission token. createContinuable independently repeats authorization at its native effect boundary, including after a successful earlier preflight. An explicit cwd is also a file-scope decision: the native patch's existing-directory/X_OK validation alone is not authorization. Both checks resolve ctx.sandboxPolicy.resolve({ session: actualParent.session }) and public ctx.fs targets. Under workspace-write, canonical fs.contains(parentRoot, target) must succeed; a lexical sibling or a symlink escaping the root is denied. The target must be an existing directory with a canonical same-world host/process path. Symlink aliases are rejected with unsupported and guidance to supply the canonical path rather than silently changing the binding's requested identity. Missing filesystem/policy interfaces or an unavailable host/execution mapping fail closed for explicit cwd only. Ordinary omitted-cwd delegation still inherits natively and does not acquire these extra prerequisites.

The parent Agent/session identity and cancellation are checked after asynchronous resolution/metadata steps. Current policy and public provider mapping are revalidated synchronously immediately before native dispatch; a policy switch cannot carry stale cwd authorization into creation. Cordis can return distinct scoped wrappers for one service, so wrapper-object pointer equality is not used as provider identity. Opaque FsTarget keys are never parsed or manufactured by production authorization code.

A delegation that omits `worktree` records an **inherit** intent (`requestedCwd: null`) instead of no relationship: the lane is visible from creation to cleanup, and `confirm` binds it to whatever actual cwd the native child header reports (an explicit cwd still must match exactly). Each binding also carries the `ticketIds` the lane works, so lanes are traceable per ticket; a ticketless research lane records no ticket field.

No sandbox-mode override, extra write root, model route/effort, or approval request enters this port. Read-only delegation does not gain writes by changing cwd: native delegated permission inheritance remains authoritative. Existing danger-full-access may bind an ordinary existing canonical directory under its already-authorized mode; this is not a policy upgrade. Under workspace-write, child cwd may narrow the parent's existing writable root, never widen it. This is a technical existing-permission boundary, not a new business/disposition approval system or Git lifecycle manager. It does not promise an atomic directory ownership lock against hostile filesystem mutation after authorization.

[Collaboration Host probes](<../tests/host-collaboration.test.mjs>) exercise the public creation/service/tool seams. Their filesystem/policy doubles implement provider-owned target and current-parent policy semantics; an additional probe uses the actual installed public LocalFs with real temporary directories and symlinks. Native creation in these authorization probes remains an explicit inbox-acceptance double, not a claim that the SDK cwd patch is deployed or that a real AgentLoop/model ran. The original Host suite plus collaboration suite pass 50/50 with the SDK path configured, and source noEmit type checking passes.

## Consumption and program facts

The pre-step adapter first obtains the native decision. Reject means no consumption/injection. Enter preserves native messages and startsRequestSeries and appends only newly owned snapshot messages. makeSnapshotMessage uses the independent mattpocock-controls source, snapshot form and exact named sections. It does not rewrite child results, original source/id or authorship. Post-execute preserves peer policy decisions and appends separate contexts. Dynamic prompt providers render synchronous cached projections; asynchronous reads belong to consumption.

Only actual agent/created, agent/status, agent/disposed and subagent/start/end events enter the program port. Actual Agent identity is retained when supplied/resolved, never serialized to models. Event wrappers are shallow frozen; borrowed Agents are not frozen. Report text, labels and descriptions never determine receipts. Parent attribution uses trusted Session/header/cache; lifecycle payloads omit parent.

## Native subagent activity

S is the native host's live run status: the number of descendant subagents of one owner session whose live Agent.status is 'running'. The catalog row activity field describes session residency, not execution, so an idle resident child is not counted; a natively started or woken child is counted once its id is in membership. External children (mode external, no local Agent) are never counted.

Membership comes from the durable catalog - HostPorts.nativeSubagentActivity(ownerSessionId, signal?) reads ctx.subagents.listDescendants, with a recursive listChildren walk as the fallback when only direct children are exposed - and is refreshed only at membership-change nodes: agent/created, agent/disposed, subagent/catalog, an unknown subagent/start-end id, the first baseline read, and a read that finds a live descendant the membership does not know. agent/status events update the count with zero walks. A normal read is O(live agents) in memory and performs no catalog IO while membership is fresh; the snapshot freshness key includes the counter revision and the live-agent count, so a cached projection can never hide a new child, an open item or a degradation.

known is true only when the whole traversal succeeded without a kind:'diagnostic' row; then running is exact. A missing service, a rejected root listing or any corrupt/unsupported/unavailable diagnostic row returns known:false, a mechanical reason naming the cause, and the readable running rows as a stated lower bound. A missing service or rejected listing is never reported as 0-with-known-true.

A run that was counted running and leaves the running set on the same runtime with fresh known membership, with no subagent/end and no agent/status idle transition, is an actionable silent stop. nativeStops carries one deduped item per child (itemId, sessionId, observed, and the last known managed lane or persisted binding when one exists); the private notifyOwner path wakes the owner once per item, and the item clears when the child is observed running again or a late end arrives. Baseline reads, plugin hot reload and a DSH restart are attributed as re-establishment through the durable knowledge.runtimeId and never produce an item or a wake; nativeCount states reestablished plus the replaced runtimeId. An unreadable catalog never yields a silent-stop claim - only the stated lower bound. NativeSubagentStop health rows name the child; a repeated unrecovered mismatch turns S into the stated lower bound with reason native-subagent-silent-stop.

HOST_CAPABILITIES.allNativeWakeAdmission reports supported only while that seam is actually loaded, and the execution-admission health row is current exactly when S.countKnown is true. Execution leases remain the audit trail for this plugin's own dispatches; they do not feed used, the capacity comparison or the injected snapshot.

## Owner notification delivery

Startup retries for already-live owners wait on notificationObserverReady. Host resolves this deferred promise only after actual source/receipt and lifecycle registrations are installed; runtime factories return without awaiting background notification flush. Teardown aborts the mount lifetime and resolves the barrier, so a failed mount cannot leave a waiter stranded. No inbox/model delivery acknowledgement is fabricated by this readiness signal.

The private notifyOwner port accepts only notificationId, ownerSessionId, instrumentInstanceId, businessRevision and authorPrincipalId. It finds the exact already-live root Agent and calls native steer; it does not load/resume cold Sessions, create an Agent, wait for the sender to finish or infer a business outcome. Cold roots return offline. Main runtime owns the durable notification outbox and retries pending/accepted-but-unacknowledged logical notifications when the Root is actually created. Notifications do not clear business pending/awaiting fields, approve actions or rewrite task status.

Every attempt creates a fresh native MessageId with the independent mattpocock-controls-notification producer, notice form, summary at most 120 characters and actual logical id/revision/author/instance metadata. The logical notificationId remains stable across retries. Delivery is at-least-once: a retry may duplicate a previously accepted notice, and this adapter does not promise exactly-once delivery.

Native steer acceptance is not delivery: the SDK parks steering at the nearest step and reject/cancel/dispose can discard it (installed dsh-agent/lib/types/runtime-types.d.ts:194–200). Preparation and inbox claim are never acknowledgements. The Host watches only its privately minted MessageIds on the exact owner Session and exact producer metadata. The actual Session user/message post-append feed is still only an in-memory commit (dsh-session/lib/types/index.d.ts:52–69, 208). After all synchronous append observers have buffered, it awaits the public SessionStore.flush(session) checkpoint. Only a successful true result — at least one durability participant and all participating listeners settled successfully (423–435) — invokes the private notificationCommitted program callback. Missing participant, unavailable store, failed flush, wrong producer or model receipt prose never acknowledge delivery. The callback is not a model tool or Remote method.

Mechanical probes use actual SessionStore.create/append/flush with an isolated gated persistence peer, not an AgentLoop/model or claimed real-disk durability certification. They prove accepted-but-not-committed, pre-step no-ack, checkpoint gating, no-participant no-ack, failed-checkpoint no-ack and wrong-source no-ack. The controlled execution wrapper additionally binds concludeTurn and deferContext to the original SDK execution object; copying a this-based SDK method would silently lose the authoritative result marker/context association.

## Unsupported guarantees — explicit capabilities

| Requirement | Installed Host / adapter behavior |
| --- | --- |
| Initial per-child continuable cwd | **unsupported**: seed-only preparation and inherited parent cwd. No header/chdir/catalogue manipulation. |
| All-native start/wake S admission | **supported when the loaded host exposes the subagent catalog listing**: every descendant of an owner session, including natively started or woken children, is enumerated into membership at membership-change nodes and its live Agent.status drives S. This is observation, not a veto — tool guards still do not cover every direct Service/Agent inbox/Remote wake, so no path becomes gated. |
| Exact native activity after restart | **known only when the catalog traversal succeeds without diagnostics**: then running is exact. A missing service, rejected root listing or any corrupt/unsupported/unavailable diagnostic row returns known=false with a mechanical reason and the readable running rows as a stated lower bound, never a guessed empty list. A new runtime re-establishes membership and count from live facts (nativeCount.reestablished) and never reports the replaced runtime's count as a stop. |
| Closing every native/cold resource re-entry | **unsupported**: lifecycle port returns closed=false/nativeColdResumeClosed=false. Resource code must retain rather than delete a resumable resource. |
| Worktree plus external common-Git-dir write grants | **unsupported**: native file policy has one workspaceRoot, no multi-root Git-ref whitelist. |

T intent, authored records, GUI/context projections and honest lifecycle observations remain independent. An S count is never inferred from a managed tool existing or from an empty registry list; it is either the native catalog result or an explicit lower bound. Fake program-gate tests can prove future supported composition paths, not certify these missing installed seams.

## Confined typed Git and filesystem

The trusted gitRunnerForSession requires an existing live Session; it never activates a model for resource requests. It reads current native policy, resolves canonical git, uses plain argv and sanitized GIT_* environment, captures bounded complete output, applies a cooperative deadline, awaits managed-range quiescence and calls actual sandbox.confine for every non-full-access process. Missing/partial confinement, truncation, runner failure and cancellation fail closed. No wider mode/root or unconfined retry is substituted.

The resource adapter's exact accepted prefix is git, --no-optional-locks, --no-pager, -c, core.hooksPath=/dev/null followed by the whitelisted verb at index 5. The full prefix and verb are checked before lookup; altered hooks, missing protective flags, old prefix and arbitrary config verbs are denied. The adapter's typed vocabulary is accepted, not arbitrary model shell commands. A concrete adapter + actual Host runner composition probe completes borrow, plan/create and inspect using fake metadata/process/confinement peers while retaining real authorization/lookup/routing; individual handcrafted argv probes alone were insufficient to catch earlier prefix drift. Content reads/listings use ctx.fs. Stable inode/readlink metadata absent from that seam uses Node metadata only after processPathFromHostPath(path) equals path proves same-world mapping. Device/inode tokens use bigint lstat results converted directly to decimal strings, without lossy Number coercion. Other backends receive unsupported, not guessed local identity. Linked-worktree metadata outside a workspace-write root remains denied.

This is not a network sandbox or adversarial repository/Git-config sandbox. Repository configuration remains an execution input; automatic checkout filters require separate scrutiny. Hooks/fsmonitor/external-diff/pager redirection are disabled. Semantic discard/integration judgments belong to authors, not this runner.
