## 1. “不当业务裁判”不等于“完全不引导行为”

| 层次 | 所属责任 | 能力/限度 |
|---|---|---|
| 程序强制 | 插件/受支持宿主路径 | 按当前配置/实例账本取得 T/S，原子准入，技术身份/租约/资源保护；没有覆盖的入口如实标为未支持，不靠提示词补成硬保证 |
| 最小仪器协议引导 | 插件随启用状态提供 | 说明 T/S 区别、准入/更新方法、逐项补入、程序释放与业务处置区分、有效工具与拒绝诊断 |
| 任务/业务/调度约定 | Skills、用户项目指令、用户与 agent 的约定、模型判断 | 什么算完成/暂停、谁来裁决、是否优先收尾、如何分工和保留资源；可调整，不被仪器新增审批或证明标准 |

用户明确开启窗口就接受其约束和最小使用协议；关闭窗口不能只隐藏数字、仍悄悄保留同样的行为要求。显示开关与功能开关依然分开。

## 2. 项目指令适合调优，但不应成为唯一功能载体

用户在自己项目的 AGENTS.md 中调整调度偏好和 workflow 约定是合适方向；本插件不自动创建、覆盖或修改这些文件。这里说的是用户项目文件，不是本插件仓库的 AGENTS.md，也不修改 vendored Skill。

插件仍承担不可缺少的最小协议与有效状态注入：用户不应先写一篇项目指令才能知道工具如何使用、哪些窗口开启或当前是否有空位。

- 插件规则只保留如何使用已启用机制；不内置大篇幅未经验证的“最佳工作流”。
- 用户文件可描述新票/收尾的选择、何时更新业务状态、是否复用上下文、何时检查资源和何时找用户；这些偏好不会变成插件自己的业务 gate。
- 容量、启停和当下占用以生效配置/程序投影为准，不在项目文件中重复硬编码 T=3/S=2 等动态数值。项目文本不能悄悄替代配置开关或容量；需要变化时使用有权限的配置路径。
- 可提供人工复制的短示例；版本/验证情况只在示例正文之外的必要文档备注、开发记录或 release 说明中简述，不放入建议复制/注入的提示词正文。第一版不额外造任意自定义提示词编辑器或文件覆盖优先级系统。
- 业务文本/项目文件中的恶意或冲突指令不授予新系统权限；遵守现有指令层级与宿主权限，仪器不解析自然语言自行改变配置。

## 3. 双窗口最小协议应包含什么

以下是内容范围，不是已验证或已装载的提示词：

1. 本实例当前是否开启、T/S 各自的含义、占用/空位和最新 revision；无票任务的 T 不适用，S 仍计数。
2. 在受管新票准入、start/idle-cold wake 前使用对应的准入操作；快照用于安排，操作时重新核验。普通运行中 relay 不创建额外执行名额。
3. T/S 独立：程序结束释放 S；模型按任务约定更新票处置及 T 占位。不要把一次执行返回直接当成交付，或用业务文字伪造程序关闭。
4. 一个 slot 释放后可以安排一个下一项工作，不等待其余任务整批完成；是否填入、选择哪项，由模型结合任务约定决定。
5. 达到上限时使用现有合法执行/等待真实相关事件，不反复尝试同样被拒绝的启动，不自行提额/关机制绕过窗口；明确授权的配置变化仍可走配置入口。
6. 准确更新自己的业务处置/占位决定，不能只为腾名额填写虚假完成；仪器不检测业务真实性或要求通用集成证明，质量依赖任务约定和模型表现。
7. 技术拒绝/未知状态提供原因与可执行下一步，不自动变成新裁决或业务暂停；业务安排仍由模型判断。

其中 1–3 和计数规则属于机制必要说明；调度优先级等优化先放用户项目约定，不把“优先全部 merger”或“保持窗口永远满”作为统一强制策略。

## 4. Worktree 生命周期：协议强约束＋轻量收尾提醒

- **强约束说明：** 哪个真实目录/资源属于当前 assignment、owned/borrowed 区别、写入/恢复引用、执行信号不等于可删除、退休操作如何请求并返回技术检查结果。
- **轻量行为引导：** 在资源创建/绑定、任务交接、相关执行返回、模型决定不再续用或工作流收尾等有意义节点，更新保留/处置说明并考虑可退休资源。自动快照列出遗留树及相关原因，不要求模型每轮手工查询。
- **业务自主：** 是否还需补修、哪个现场有价值、此时保留还是退休，由模型按任务约定决定；不强制“必须全部合并才能退休”、每次找 owner 确认或 N 分钟空闲自动清理。
- **避免骚扰：** 对长期 retained 的事实不自动判为失败或频繁催问；变更提醒合并，明确保留理由可记录而非反复制造问题。
- **真正执行的保护：** 不因为温和收尾提示就自动删树；明确请求之后仍核验准确目标、实际租约/跨实例引用、冷恢复入口与文件现场，现有权限不变。技术可退休与业务上应该退休分别表达。

## 5. 注入、关闭和历史提示

推荐分开短协议说明与当前状态快照：实例初始化/恢复/相关功能变更时提供有效协议，状态变化与原生结果消费时自动刷新快照；要在实际模型输入中验证 compaction/冷恢复后仍能发现协议，避免每次 heartbeat 重复长文。规格明确：模型可见正文只含有效规则、工具使用与当前运行事实，不注入提示词开发版本、“候选/未验证”或类似成熟度说明；必要的配置/账本 revision 是运行事实，不是提示词验证声明。

只针对已启用、已解析实例/assignment 的范围；父 coordinator 的全实例和 child 的分配范围要区分，不往所有 Skills/session 全局灌同一段流程。项目自定义约定按 DSH 原生指令机制装载，不伪装成插件或用户新授权。

窗口关闭后，新工作不再受本插件窗口准入/窗口行为要求；已接受执行不强杀，旧账本和实际资源引用保留，如何交接/收尾在配置变更中明确。若保留旧受管对象的短暂 draining，也只说明其技术状态，不无限要求用户继续按已关闭的策略调度。其他宿主原生配额/权限仍独立存在。

旧提示已经进入历史上下文，不能保证物理删除。应注入当前功能已关闭/配置 revision 的明确说明，使先前窗口协议不再被当作当前要求。关闭显示不产生此效果；关闭功能才改变有效协议/准入。精确旧对象交接和热变更仍是待验证设计，不声称已有原子迁移实现。

## 6. 没有验证提示词时怎样推进

- 先准备极短候选协议；其版本/来源与验证情况留在开发记录、必要文档备注或 release 说明中简述，不进入模型可见提示词、附加上下文或面向模型的诊断文本。默认功能关闭，显式启用时只应用规则/工具说明及运行状态。
- 先做无模型验证：捕获实际模型输入中的启用/关闭协议、快照/身份，另在测试记录关联提示词版本；断言模型正文没有版本/未验证声明。验证 T/S 原子计数/单项补入、单子父/冷恢复/错代次、更新降级、资源保护和关闭后旧提示失效说明。它证明机制，不证明模型会合理更新业务状态。
- 行为验证需要另行授权的小型真实模型试验：比较最小协议、最小协议＋用户项目约定；任务/模型/工具路线固定，记录 prompt/配置版本与原始工具/程序事件。
- 观察机械越额、错误/过早票占位更新、空位长期不用、无意义启动重试、整批等待、过量裁决请求、遗留树/误删和上下文开销；票业务正确性按该试验任务已有标准评估，不增加运行时业务裁判。
- 先调整项目约定和候选引导；只有重现的共性协议问题再修订内置短说明。用户自行调优不是“用户承担验证插件正确性”的替代。

本轮未执行上述无模型接入验证或真实模型试验，也未产生经过验证的仪器提示词。

## 7. 仍需面对的边界

1. 强制只能覆盖实际受控 start/wake/assignment 入口；提示词无法补齐尚缺的宿主 gate，不允许把“模型遵守”宣传成“所有路径被程序强制”。
2. T 能强制准确计数模型申报的占位，不能在不做业务裁判的前提下保证模型申报一定正确。这是显式责任分工，不是再加隐藏验证 gate 的理由。
3. 项目指令＋短内置协议可能重复或冲突；动态配置与快照只有一个真值，业务偏好由现有指令层级决定，不设计第二套优先级系统。
4. 长期保留资源、S=1 的嵌套等待、未知事件/重启、关闭后已接受工作，仍需要有界技术处理和明确诊断；不用模型猜测释放、静默清账或自动制造审批。
