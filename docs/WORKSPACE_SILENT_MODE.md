# 工作区三态与模型静默（2026-11-27）

本契约取代旧工作区／全局协作总闸 OFF 时仍向模型保留工具、说明和收尾入口的行为；不改变启用协作时各子功能的权限和必要收尾。

| 生效状态 | Skills | 协作 |
| --- | --- | --- |
| 停用 Matt Pocock | 不列出、不加载本包技能 | 无 |
| 仅启用 Skills | 正常分发 | 无 |
| 启用 Skills 和协作管理 | 正常分发 | 仍按全局、工作区和各子项生效 |

- 复用 `skills.enabled`（安全初值开）和 `workspace.enabled`（安全初值关）及其稀疏继承，界面把后者称为「本工作区协作管理」。协作依赖 Skills；全局协作总闸关闭时最多只有 Skills。读取旧配置不得让 Skills 关而协作开；不自动迁移存储。用户关闭 Skills 后开启 Skills 先回到仅 Skills，协作须显式开启；后端保存也要阻止组合或继承导致的隐式重开。T/S、显示和其余细项保留；无业务数据迁移。
- 无协作时不向新模型请求添加本插件的任何协作工具（含 controls、audit、delegate）、协作系统指针、状态、上下文、通知或 OFF 说明。隐藏并拒绝直接调用与 PTC 调用；对已解析的旧调用集合，在插件效果边界重查最新策略。原生执行不被拒绝或取消。不做新的协作观察、持久记账、唤醒或通知，不因开关自动结案、release 或删数据。重新启用后原权限与保留数据继续有效。在途操作不能撤回已提交的事实。
- 覆盖既有、新建、冷恢复会话和所属子代理；沿可信会话／父链工作区归属，不靠浏览器选中项或任意可变 cwd，不因切 worktree 而重启插件。独立且有权认定的另一个工作区按自己的策略生效。无法核验归属或策略不得开启协作或使已知停用回退为开启。
- 停用后，本插件 Skills 必须从候选发现、内容访问及缓存实际消费中消失；仅过滤本包候选，不改变项目／用户技能、vendor、channel 或 provider 优先级。协作静默不是擦除用户可见的旧聊天、已发模型请求或已存在记录；但本插件拥有的旧运行状态注入不得在后续请求回放。
- 仅用户主动打开 Web 插件设置时仍可读写配置和重新启用，沿用授权和 revision 检查；静默时不显示会话协作入口、摘要、提醒或新插件会话呈现。用户设置不依赖模型工具；不增加替代提示／旁路。

## 验证和交付

公开验证入口：策略保存与生效解析、Web 工作区设置、宿主 Skills 实际发现／读取、模型请求及 native/PTC 工具调度、实际宿主事件及其公开查询。同一 profile 两个工作区验证隔离；覆盖三态和转换、继承及旧存储、旧会话下一次请求、子代理和工作树、缓存/冷恢复、失效竞态、原生操作与旧记录保留。明确列出目前 SDK 若不能提供的真实保证，未通过不得称作彻底静默。

从 0.24.0-alpha.1 兼容基线隔离开发和测试，锁定目标 DSH 0.2.3-alpha.2；完整建设、源码、真实运行时和精确制品通过再非 force push、新 prerelease、下载验同一制品并使用官方入口安装到现有本机 Web Profile。安装与当前服务实际激活/GUI 验证分别记录。不重启或替换现有服务、不改共享 SDK、不自动启用生产协作、不 npm publish、不覆盖旧资产。

## DSH 0.2.3-alpha.2 隔离候选的实证与发版边界

- [真实 AgentLoop 探针](<../tests/workspace-silent-host.test.mjs>)在同一既有会话先开启、再关闭协作，捕获 Native 和 PTC 的下一次常规请求。可确认已识别的旧插件状态／声明被排除，同时保留普通对话、其他工具和原始聊天事件。对原生工具声明使用宿主请求序列重建；仅对宿主明确标注的、能按已验证格式定位的 PTC 声明做窄范围投影。无法可靠定位旧内容时不猜测、不修改原始历史。
- **当前宿主未通过严格发版门槛。** 原生自动压缩可在第一条静默常规请求提交新工具声明前发出独立模型请求。实际 [原生压缩反例](<../tests/silent-compaction-known-limitation.test.mjs>)证明旧插件正文已经从工作面移除，但这条压缩请求仍携带旧请求头里的插件工具声明；现有公开接口不能按会话过滤该请求。已计算的步骤工具集也不会因稍后的保存而重新组装；只能在插件效果边界重新授权，不能把这误报为所有尚未发出的请求都已静默。不能为规避而伪造宿主请求头、禁用原生压缩或改共享 SDK。
- 活跃会话的技能查询使用真实 Agent scope；目标宿主的冷 Web 斜杠菜单只提供 preset scope，无法按可信会话确认，候选因此保持隐藏。已经打开过的原生浏览器菜单可能暂留旧条目，服务器实际发现／加载不会因该缓存获准。缺少工作区和策略 Host 接线的原生 CLI 在此候选中拒绝分发，不能冒称保持旧版 CLI 默认行为。正式兼容还需要宿主提供可核验的冷浏览目录/CLI 归属和缓存失效接口。
- 本节记录尚未通过的候选与宿主边界，不修改上方用户契约，不授权发版、安装此不完整候选或改动现有 Web 服务。
