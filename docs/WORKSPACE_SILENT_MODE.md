# 工作区三态与模型静默（2026-11-27）

本契约取代旧工作区／全局协作总闸 OFF 时仍向模型保留工具、说明和收尾入口的行为；不改变启用协作时各子功能的权限和必要收尾。

| 生效状态 | Skills | 协作 |
| --- | --- | --- |
| 停用 Matt Pocock | 不列出、不加载本包技能 | 无 |
| 仅启用 Skills | 正常分发 | 无 |
| 启用 Skills 和协作管理 | 正常分发 | 仍按全局、工作区和各子项生效 |

- 复用 `skills.enabled`（安全初值开）和 `workspace.enabled`（安全初值关）及其稀疏继承，界面把后者称为「本工作区协作管理」。协作依赖 Skills；全局协作总闸关闭时最多只有 Skills。读取旧配置不得让 Skills 关而协作开；不自动迁移存储。用户关闭 Skills 后开启 Skills 先回到仅 Skills，协作须显式开启；后端保存也要阻止组合或继承导致的隐式重开。T/S、显示和其余细项保留；无业务数据迁移。
- **模型准入以保存 OFF 后新准入的 DSH 步骤为界。** 无协作时，新步骤不携带任何本包协作工具（含 controls、audit、delegate）、协作系统指针、状态、上下文、通知、归属本包的旧状态／声明回放或 OFF 说明。已组装或已准入的步骤，包括同一步内重试，仍按宿主原流程完成；不追改、重建或取消这些步骤，也不撤回已发请求或擦除原始聊天和记录。
- **插件效果以最新策略为界。** 保存后立即在插件实际效果边界重查，即使直接／PTC 调用来自已解析的旧工具集也拒绝其插件效果。不做新的协作观察、持久记账、唤醒或通知；不拒绝或取消原生执行，也不撤销已提交的事实。不因开关自动结案、release 或删数据。重新启用后原权限与保留数据继续有效。
- 覆盖既有、新建、冷恢复会话和所属子代理；沿可信会话／父链工作区归属，不靠浏览器选中项或任意可变 cwd，不因切 worktree 而重启插件。独立且有权认定的另一个工作区按自己的策略生效。无法核验归属或策略不得开启协作或使已知停用回退为开启。
- 停用后，本包 Skills 在按可信会话核验的宿主实际发现／加载中不列出、不加载；浏览器或宿主缓存不得替代实际消费时的策略授权。仅过滤本包候选，不改变项目／用户技能、vendor、channel 或 provider 优先级。原生冷／暖 Web Skills 菜单能否即时显示最新候选不是本批发版条件。
- 仅用户主动打开 Web 插件设置时仍可读写配置和重新启用，沿用授权和 revision 检查；静默时不显示会话协作入口、摘要、提醒或新插件会话呈现。用户设置不依赖模型工具；不增加替代提示／旁路。

## 验证和交付

公开验证入口：策略保存与生效解析、Web 工作区设置、可信宿主会话的 Skills 实际发现／读取、模型步骤准入及 Native／PTC 工具调度、实际宿主事件及其公开查询。同一 profile 两个工作区验证隔离；覆盖三态和转换、继承及旧存储、既有会话的下一个新准入步骤、子代理和工作树、缓存／冷恢复、效果撤销竞态、原生操作与旧记录保留。

发布前令 `DSH_CONTROLS_HOST_ROOT` 指向与 `engines.dsh` 精确匹配的已安装宿主，运行 `node scripts/verify-silent-request-readiness.mjs`。[准入门禁](<../scripts/verify-silent-request-readiness.mjs>)覆盖五项真实 Host 用例（Native／PTC 的常规和在途切换，共四项；另查旧工具集效果拒绝与工作区隔离）和六项从 OFF 状态进入的压缩用例；不要求重新投影已组装的请求。

从 0.24.0-alpha.1 兼容基线隔离开发和测试，锁定目标 DSH 0.2.3-alpha.2；完整建设、源码、真实运行时和精确制品通过再非 force push、新 prerelease、下载验同一制品并使用官方入口安装到现有本机 Web Profile。安装与当前服务实际激活/GUI 验证分别记录。不重启或替换现有服务、不改共享 SDK、不自动启用生产协作、不 npm publish、不覆盖旧资产。

## DSH 0.2.3-alpha.2 的诊断与限制

- [真实 AgentLoop 探针](<../tests/workspace-silent-host.test.mjs>)分别捕获既有会话的 Native 和 PTC 请求。对新准入的静默步骤，仅排除已识别的旧插件状态／声明；保留普通对话、其他工具和原始聊天事件。原生工具声明按宿主请求序列重建；PTC 仅投影宿主标注且能按已验证格式定位的声明。不猜测缺少可靠归属的历史内容，不修改原始历史。
- 原生自动压缩可先于新工具声明发出独立请求。[未加过滤的宿主基线](<../tests/silent-compaction-known-limitation.test.mjs>)显示这类请求可带旧工具声明；候选在公开 `llm/stream` 入口只为身份已核验、在该入口已处于 OFF 的单次压缩输入移除本包归属的内容。[压缩验收](<../tests/silent-compaction-input.test.mjs>)覆盖正文、工具历史及声明、其他上下文、下游中间件、用量、重试与取消，不改变原生压缩策略。
- **适配器前等待是诊断，不是发版阻塞。** 若 Native／PTC 或[辅助压缩](<../tests/silent-compaction-final-handoff.test.mjs>)请求先组装、在下游等待时才保存 OFF，DSH 仍可能将旧声明和快照交给适配器。该现象不代表新准入步骤失守，也不免除旧调用的即时效果复核。详见[宿主兼容性说明](<DSH_SILENT_REQUEST_COMPATIBILITY.md>)；不为规避而伪造请求头、禁用原生压缩或修改共享 SDK。
- **菜单可见性不是加载授权。** 冷 Web 斜杠菜单的 provider 只收到共享 preset scope，无法核验唯一会话，因此不列出本包候选；已打开过的原生菜单可能暂留旧条目，公开的宿主缓存失效不会同步清除浏览器缓存。活跃会话使用真实 Agent scope；实际宿主发现和加载始终按经核验的会话策略，缓存命中也不能绕过检查。缺少工作区和策略 Host 接线的原生 CLI 不分发本包 Skills；不猜测归属，不回退到全局允许。这些菜单限制不替代活会话宿主加载验收。
- [原生观察撤销探针](<../tests/workspace-silent-native-counter.test.mjs>)覆盖已经观察的工作区：保存关闭后撤回观察许可，拒绝迟到的目录／子会话结果并停止后续分类；重新开启时基于当前运行状态重建基线，不补录该观察器关闭区间内的运行终态。对照工作区继续记录，宿主原生运行不停止。冷工作区归属未核验时保持未知，不回退为跨会话读取或发送通知。不能据此证明[工作树历史补登记](<WORKTREE_OBSERVATION.md#2026-11-27-工作区静默在途回放已撤销历史区间仍不可证明>)的原始策略区间。
