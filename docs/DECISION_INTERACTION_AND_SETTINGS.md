# 裁决交互偏好、用户提醒与原生设置页整理

- 日期：2026-11-06。
- 状态：所有者已认可并授权先固定文档，再由 subagents 在隔离环境开发、测试、push 与发布；目标 0.14.0，隔离开发与回归中，尚未集成验收/发布。
- 权威入口：[DESIGN.md](<DESIGN.md>)；阶段门禁：[IMPLEMENTATION_PLAN.md](<IMPLEMENTATION_PLAN.md>)。
- 不为本机安装，不改当前 Profile/共享 SDK，不重启服务，不 npm publish。不修改 vendored Skills、渠道/provider 优先级或宿主消息机制。

## 1. 范围与职责

同一份 decision 账本只增加交互偏好，不新增裁决审批标准、第二套问题记录、裁决消息队列或调度器。是否需要裁决、必要信息、业务依赖与落实由 Skills、用户约定、任务文档和模型判断；字段继续遵循[现有记录契约](<INSTRUMENT_RECORDS.md>)，不把建议/影响/阻塞范围升级为新增必填字段。

插件负责登记/呈现/提醒；DSH 原生 Session 下方输入框负责用户输入、发送与原生排队/插队；agent 理解答复并显式更新原 decision。保留现有显式 DecisionEditor，但它不是异步模式必经入口。不监听聊天文本自动判决，不接管 composer，不造专用答复输入框或排队/插队按钮。

## 2. 两种偏好，同一个引导模板

在现有全局默认/工作区覆盖策略中扩展 pendingDecisions.interactionMode，允许 native-question、async-decision；缺省为 native-question（只在裁决功能实际 configured 时激活引导），保留 enabled 的原语义。恢复继承删除叶字段，旧缺字段配置可读，未知枚举拒绝。有效策略保留模式与来源，并随真实 config revision 进入模型消费/去重，不能只在设置页显示。

公共模板：

> 需要用户裁决时，沿用现有裁决约定，登记或更新对应 decision；{提出渠道}；{等待方式}。

| 模式 | 提出渠道 | 等待方式 |
|---|---|---|
| 原生提问优先 | 优先通过可用的原生提问工具提出 | 按原生问答流程接收答复 |
| 异步裁决优先 | 优先通过裁决仪器提出，由用户通过 DSH 原生会话消息答复 | 不原地等候，继续处理不依赖该裁决的工作 |

英文模型引导由一份公共模板加模式片段生成；不得各维护一套裁决信息规范。共同约束只写一次：未答/跳过/关闭不是许可，不擅自代替用户决定；只阻塞实际依赖动作；无独立工作时允许正常结束当前轮，未决不冒称整体完成。原生提问不可用/取消时不循环重试，保留未决并明确降级；owned child 按宿主限制将问题交回主代理。异步模式不为等待答复调用阻塞式提问工具。偏好是模型引导而非硬拦截，不能越过更高优先级指令、明确的等待确认、宿主权限或任务约定。

管理/裁决功能 OFF 时不命令新增 decision 或继续执行旧模式协议；保留已有记录收尾与义务，明确当前偏好未激活。不能因写入失败而声称已登记，也不能静默开启功能。

### 2.1 原生机制事实边界

本次只读核查对象为已安装 DSH 0.2.2-alpha.3，不外推 alpha.2 runtime：

- SDK 包相对定位 @deepseek-ai/dsh-tool-ask-user/lib/index.js：mode 默认 legacy，execute 等待 userQuestions.ask；timed 必须显式启用，120 秒并非 legacy 的默认异步超时。
- @deepseek-ai/dsh-agent-loop/lib/index.js：steer 发往 next-step，followup 发往 next-turn，cancel 才 abort；普通插队不是立即中止当前工具，也不会自动完成正在等待的 legacy ask。
- 未定位公开的原生用户响铃服务；不能宣传提问或尾部问题必定触发声音通知。不修改宿主配置以强开 timed，不以 SDK patch 为本功能依赖。

## 3. 用户提醒独立于 agent 更新通知

现有 notifyOwner 是账本变化到主 agent 的 steering/持久回执路径，原语义不变；本节是浏览器内的操作者提醒，不互相借用 consumed/ACK，也不产生模型调用、业务写入、已读或授权。

### 3.1 本浏览器个人设置

设置页明确标为“本浏览器提醒”：仅保存在当前同源浏览器的插件自有命名空间，不保存到业务策略、不要求 agent 修改、不承诺跨设备或用户账号同步。损坏/不可用存储诚实提示并使用非持久安全初值，不静默报保存成功。

| 设置 | 初值/范围 |
|---|---|
| 声音通知 | 关闭，显式 opt-in |
| 铃声持续时长 | 5 秒；整数 1–60 秒，含 3/5/10/30 预选或数字输入 |
| 音量 | 50%；0–100 |
| 页面内通知 | 开启；非模态、不抢焦点 |
| 页面内通知关闭时长 | 8 秒；0 表示手动关闭，其余整数 1–60 秒 |
| 桌面通知 | 关闭，用户手势显式请求浏览器权限后才可能可用 |

提供试听、停止当前铃声、通知可用性/权限状态。试听只由显式点击触发；AudioContext 被拒绝/挂起、Notification 不可用/权限拒绝、非安全环境或后台节流均如实显示，不把开关冒充送达证明。声音有限时长，退出/卸载可靠停止；不引入无限响铃、超时升级、周期催促或远程音频资源。桌面通知时长由浏览器/OS 控制，不伪装成可强制配置；关闭浏览器后不承诺通知，不装 Service Worker 或额外后台服务。

### 3.2 来源、范围与去重

- 仅以当前授权的 pending===true && addressee.kind===user 为待用户裁决；不从 blocker/自由状态/聊天关键词推断。
- 覆盖本浏览器已打开且宿主仍挂载的会话（含保留挂载的后台标签）；不以面板展开、inputSummary/header/rightPanel 的显示开关作为是否通知的条件。宿主取消挂载、关闭网页、未打开的 Session 不在覆盖承诺内，设置页说明此范围。
- 复用已授权会话观察与现有 Remote；不得为提醒新建 owner、唤醒冷 Session、轮询所有冷会话或重复取得全历史。无 UI 通知订阅 seam 时采用有限已挂载观察，隐藏页面遵循宿主/浏览器实际节流，不声称实时推送。
- 按 caller/owner instance、workflowId、decisionId 和本次进入待用户裁决的阶段去重，而不是只比较总数。重复刷新/普通文字修改/viewer read-hidden/无关票变化不重响；总数不变的新问题要能提醒，真实 reopen 可再提醒。
- 优先从已获授权的 decision/history/current revision 识别阶段，不因 history 缺失/清理或 unknown 伪造完整事件覆盖；只消费实际可证明的新状态，初次加载的已有待决作为积压提示，不逐条补响旧事项。读取故障/撤权不当空集，不借恢复制造新阶段。
- 多标签页用插件自有、含真实 caller/instance 的小型通知身份协调；可用 Web Locks 时互斥并配合有界本地去重。无跨标签互斥能力时明确 best-effort 限制，不承诺 exactly-once；不存业务正文、不无限增长去重表。
- 声音和弹窗共享通知身份。打开详情、关闭弹窗、停止铃声只影响提醒本身，不自动改变 pending、awaitingImplementation、read 或 hidden。

## 4. 阅读详情必须能与原生输入并存

裁决详情不是 hover/失焦即关的菜单。点击原生输入框、输入、选中/复制文字、焦点切换、agent 工作和正常刷新不关闭详情，不自动换到新事项、不抢焦点或滚动位置；新增通知和通知计时结束也不得关闭已打开的阅读区域。

用户主动打开的事项在同一合法 Session/实例内保持到手动关闭/收起或切换查看对象。pending 数归零、事项已解决/移入其他分区时不突然消失：已打开的内容显示当前“已更新/已解决”，必要时保留本次阅读的受权内容并清楚标明，不把其当当前未决；默认其他区仍折叠。通知 toast 与持久详情分离。

Session/实例切换、真实撤权、身份不一致或显示入口显式关闭时必须隔离/清理旧数据；不能为保留阅读而泄露旧授权内容。未知读取显示诊断，不冒称当前。宿主原生 slot 被 takeover/卸载时不篡改其行为，不宣称插件能阻止宿主卸载；提供正常的侧栏稳定阅读入口，不以关闭 popover 为默认阅读方式。

## 5. 设置页逻辑与显示整理

优先使用当前最低宿主可验证的 @deepseek-ai/dsh-client-ui-primitives 与 DSH 主题 token，原生可访问的表单语义。不存在合适公开控件时用普通语义 HTML，少量布局样式；不添加私有 UI 库/全局 CSS，不复制宿主组件实现，不叠加彩色自创大卡片/胶囊，不引入新的导航框架。原生 Input/Select/Switch/Button/DisclosureRow 等只能按实际 public exports/type 选用，不猜名字。

页面按操作职责分区，顺序建议：

1. 页面标题与简短范围说明；全局唯一总闸与编辑范围清楚区分。
2. 协作策略：当前范围总闸、技能分发、功能与参考上限、裁决交互偏好。
3. 界面显示位置。
4. 本浏览器个人提醒（独立保存，与服务器策略不同来源）。
5. 进阶交付监督，默认折叠，但不删除已有能力或改变独立保存/CAS。
6. 会话状态查看，默认折叠，与配置编辑分开。

保存作用域/未保存状态/生效值和来源清楚；同一策略只保留一个明确保存区。保留稀疏继承删除、原读取修订的草稿 CAS、冲突不覆盖、失败保留草稿、未知数值不猜零、两级总闸原因、技能分发独立语义。改范围不静默保存或丢草稿；背景刷新不升级草稿修订。监督 reviewer.routeMode 的合法 inherit 值与“删除覆盖”使用不同 UI sentinel，保留 wire 值并验证工作区显式 inherit 覆盖全局 explicit。说明与原始 JSON/长诊断放就近帮助/折叠技术详情，减少多层框套框和重复提示。
