# 协作区后续三项改进：研究与讨论稿

> 2026-11-09 后续所有者已认可本研究建议与推荐方案 B，授权先文档、隔离 subagents 开发测试、push/Release 并为本机安装。以下“待讨论/未获实施认可”保留为研究形成时状态；当前实施以 [DESIGN](<DESIGN.md>) 与 [本批冻结契约](<COLLABORATION_RECOMMENDATION_SUPPORT.md>) 为准，不将研究证据冒充实现或安装验收。

> **仅研究，待讨论；不是已冻结的实施规格或启用授权。** 三个 fresh subagents 分别研究摘要零值、无人值守推荐支持、S 标题与导航。本轮只写研究材料、运行隔离公开接口探针和已有基线测试，不改运行时代码、已安装插件、Profile、共享 SDK 或生产记录；不发布、安装、启用管理或重启服务。

## 1. 结论与证据层级

- **明确需求**：摘要删掉“裁决 · ”前缀，仅保留“待你裁决 N”；当前授权计数明确为 0 时隐藏这个主提醒。不是删除详情“裁决”tab，也不清记录。
- **新增能力，需讨论授权语义**：显式开启后，由限定范围、期限的预授权支持明确推荐，令 agent 不必等待用户再次答复。不能只改工具文案，也不能伪造人工即时答复。
- **已定位具体产品缺陷**：导航读取 ctx.sessions，但客户端未声明该服务依赖；真实 Cordis 拒绝读取，适配器把异常吞成不可用。在隔离探针中不改原 bundle，只补依赖作用域即可由同截图回退转为原生打开调用，不能归结为宿主没有 API。
- **标题与导航分开结论**：宿主公开标题/catalog API 和改名订阅在隔离链中可用；人类文字也可能来自 fallback label。尚未读取截图对应实际会话的标题，不宣称现场标题已正确或已修。

仓库基线为 5160d4e8a90adbf9913412b942dd7efe00a83616；官方 SDK 核查对象为 DSH 0.2.2-rc.1、Cordis 4.1.0。已安装 0.18.0 原字节和本地 bundle 分别进入隔离探针，两者都存在导航依赖缺口。上一轮恢复闪烁修复仍只是本地交付，不能拿未部署解释本轮全部问题，边界见[本地验收摘要](<CLIENT_RECOVERY_VALIDATION.md>)。

原始机器路径、源码快照及日志仅私有留存；本文是带源码定位的作者总结，不是原始生产取证，不证明当前 GUI 已更新。

## 2. 摘要去重与零值隐藏

### 已证实的现行为

[摘要呈现](<../src/client.ts#L992-L998>)无条件生成“裁决 · 待你裁决 N”；[旧测试](<../tests/client-input-summary.test.mjs#L319-L337>)还明确要求 0 时三个主入口都存在。这是当前设计，不是仅由部署状态造成。

[详情导航](<../src/client.ts#L1011-L1021>)固定为裁决/T/S，记录核对只在裁决类标题同行出现。隐藏零值主提醒后仍可从 T/S 进入裁决，因此不是彻底断链；但主动开启夜间模式和核对旧记录不应被迫走不相关分类。

### 推荐呈现

| 状态 | 主提醒 |
|---|---|
| 当前受权计数 N > 0 | 突出“待你裁决 N” |
| 当前受权计数明确为 0 | 隐藏这个主提醒 |
| records 域未知、外层仍可读 | 显示未知/诊断，不把 unknown 当 0 |
| 整体观测未知或失败 | 沿用中性恢复壳，不显示旧数/正文 |
| 明确撤权、关闭显示、真实换身份 | 继续清理，不以持久阅读绕过围栏 |

不要把零过滤上提成整条 InputSummary 返回空，否则会一起丢掉 T/S、核对与观察。依据：[轻量/full 观察](<../src/client.ts#L624-L639>)、[完整摘要](<../src/client.ts#L946-L979>)、[恢复契约](<CLIENT_RECOVERY_STABILITY.md#L25-L39>)。

建议细化，尚未批准新位置：

1. 保留详情“裁决”tab；同一合法身份下，已打开阅读在 1→0 时不突然收起，保留当前受权正文与关闭出口。
2. 有兼容记录需要核对且待用户数为 0 时，可提供灰色“记录核对”直达；不恢复醒目的零值提醒，不把旧 awaiting 标记叫未完成任务。
3. 无人值守开关在裁决展开区提供快捷控制，同时有独立设置入口，保证 0 项时也能提前开启/关闭。显示全关不应让设置消失；管理 OFF 不隐式开启。
4. 只在焦点正落于即将被隐藏的按钮时作最窄保护；普通刷新不抢输入框焦点或滚动正文。

## 3. 无人值守支持推荐选项

### 3.1 当前并不是 put-decision 硬锁停 agent

[保存核心](<../src/controls/instruments.ts#L347-L377>)只做受权、幂等和业务 CAS 保存，不等待用户或停止 agent。现行异步指导已允许继续不依赖裁决的工作，不能替用户选择真正依赖的分支：[交互契约](<DECISION_INTERACTION_AND_SETTINGS.md#L20-L29>)。

[工具小回执](<../src/model-tools.ts#L163-L198>)没有推荐执行策略。只返回“支持推荐”，却仍将记录和持续上下文保留为待用户裁决，恢复后可能再次等待；反之也不能为归零偷清 awaiting 或伪造用户答复。

工具返回不是唤醒机制：[现有通知](<../src/runtime.ts#L1233-L1249>)沿 owner 通知链，[host](<../src/host.ts#L1536-L1550>)不因此创建离线 root。子代理续聊应复用有权 parent 的原生 send_message。第一版不扫描、唤醒旧 lane，不增加定时任务；有依据继续不等于保证模型无限运行。

### 3.2 可选语义

| 方案 | 行为 | 评价 |
|---|---|---|
| A：只返建议 | 继续独立工作，依赖问题仍 pending | 改动小，但不能冒充按推荐推进依赖分支 |
| **B：预授权支持 + agent 显式采用（研究推荐）** | 用户开策略；新项工具返回受支持的明确选项；agent 在同一事项记录采用，后端重验策略/修订/权限后保存，再继续 | 无需用户逐条点击，保留显式记录链；仅返回候选而未采用不算完成闭环 |
| C：提交时后端原子采用 | 新项提交时同时按策略采用明确推荐，直接返回已采用 | 少一次 agent 记录调用，但改变“保存调用者声明”的语义；须明确原始请求、最终处置、作者来源和事务边界 |

推荐先讨论 B；若明确要求“一次 put-decision 返回时该项就已经按推荐处理”，C 更贴近这个强语义。**两者都无需用户再逐条确认**，区别是由 agent 显式记录采用，还是后端在本次提交中完成。均未获实施认可。

### 3.3 建议默认边界

- **范围**：当前 owner session/仪器实例及受权后代，不是全局/整个工作区；换工作树不改变归属，独立会话/fork 不复制授权。现有工作区策略不是 owner-instance 授权，不能改全局字段却声称仅本会话。
- **开启与期限**：默认关闭，用户显式开启并确认范围/明确到期时间；可选时长或时刻。刷新不续期，关网页不影响后端到期检查，不擅自把“夜间”固定成某时点。
- **新项**：默认仅开启后新创建事项，不扫描旧 backlog、不把旧项普通编辑当新问题。B 要在创建时绑定真实策略/新项资格，不能第二次采用时因记录已存在就误拒绝，也不信模型自报创建时间。
- **明确推荐**：当前 recommendation 是自由文本；最小方案沿用字段，但自动支持只认严格匹配唯一 options key。自由文本/label 可展示，不猜选项；理由可放背景。若要理由与推荐 key 并存，可另提独立推荐键，不强迁旧记录。
- **真实来源**：显示“按预授权策略选择”，持久保留选项 key、源修订、策略 id/修订、授权来源和实际采用作者。agent 作者仍是 agent，不写成用户刚刚亲自批准。概念字段实施前另冻结，不接受模型自报权限/作者。
- **状态和落实**：有效采用后才退出待用户队列，保留既有 awaiting、结果、引用、约束与历史，不默认新建 await、不推断落实完成。用户之后可明确修正，不声称副作用已被回滚。
- **撤销/并发**：关闭或到期废止未采用候选，不回滚此前已采用历史。提交时重验当前策略、源修订、业务 CAS 和实际 assignment；真实用户答复先到则旧采用冲突。重试不重复写，未知存储结果不冒成功。
- **不扩大操作权**：选择推荐不额外授权文件、支出、权限、外发、发布或原生工具；仍服从任务/宿主权限与明确本人确认要求。不引入关键词/LLM 风险分类审批机，不把普通实现选择都登记为 decision。
- **OFF/显示**：不自动开管理或 pending feature；保留旧记录合法收尾。显示偏好与授权独立，浏览器 localStorage 不能充当 agent 执行授权。

依据：[DecisionValue](<../src/controls/instrument-state.ts#L22-L34>)、[严格解析](<../src/controls/instrument-state.ts#L174-L192>)、[展示排序](<../src/client.ts#L789-L805>)、[真实作者与 CAS](<INSTRUMENT_RECORDS.md#L26-L46>)。展示匹配不能直接升级为执行许可。

### 3.4 真实变更面，不是纯前端开关

需要受认证 owner-instance 策略读写/持久面、可验证采用意图、持久来源、有界 typed/rendered 回执和消费说明。工具名未必增加，但严格 wire/schema、Remote、旧端兼容有实际变化，不能从自然语言“已批准”推断授权。

回执需区分仅受支持候选、已采用、不合格、冲突、未知；投影失败不重执业务写，旧回执不是当前新授权。新项资格、撤销与保存须有可证明的串行/持久边界，不能暗称不同 aggregate 已天然跨进程原子。

[当前上下文](<../src/runtime.ts#L802-L817>)不会自动常驻所有已解决结果。必要选择/执行约束应由既有任务文档或有效上下文承接，尊重 included/excluded；不用偷开 await 或批量 set-context 制造常驻。历史可查不等新 Agent 已消费。

## 4. 子代理标题与原生侧栏导航

### 4.1 具体缺陷

1. [依赖声明与传递](<../src/client.ts#L2164-L2181>)缺少 sessions，却把受限 ctx 传给导航适配器。
2. [适配器](<../src/client-subagents.ts#L37-L45>)读取 host.sessions.subagentAddress。真实 Cordis 对未 inject 服务的 getter 抛出 cannot get property sessions without inject；available 捕获为 false，按钮就显示“宿主缺少可用原生子代理导航能力或真实地址”。这是误导性归因。
3. 已安装和本地原字节 + 真实 Cordis 在隔离公开 port 链均稳定 RED；只在受控祖先作用域注入 sessions 后，两份都可点击并调用一次原生打开接口，没有改编译字符串。
4. 接入当前官方原字节 session controller 和原生 subagent 插件后，真实 catalog 有 title/parentId，subagentAddress 的参数/返回与适配器相容，地址被原生 tab codec 接受。证据不支持 API 不存在或格式根本不兼容。

宿主一手来源按包相对定位：@deepseek-ai/cordis 的公开 plugin/inject 和服务 getter，@deepseek-ai/dsh-api-session-controller 的 catalog/subagentAddress，@deepseek-ai/dsh-client-ui-subagent 的 aside action/codec。原始源码定位与探针私有保留，不冒充公开源码 URL。

### 4.2 推荐方向

- 当前有 sessions 服务时，在 outer 依赖或实际读取所在 inner scope 注入一处即可；不必重复两处。包 manifest 依赖不是服务依赖，不能靠添包名修复，也不应绕 ctx.get 生命周期。
- 直接加必需 sessions 会让没有该服务的旧宿主整个基础插件不激活。若继续保证缺能力时基础阅读可用，应保留基础注册，在独立 sessions 增强作用域发布/撤销窄导航 port，并通知 React 重渲染/卸载；不永久缓存 null。具体接口另冻结。
- 延续真实 subagentAddress → sidebarRight.openResource，保留 mounted session、当前受权快照、父子链和点击时重验，不用 raw id/owner 猜路由。
- 标题继续只读宿主 useSessions/catalog，不加模型标题字段，不维护第二份标题账本。[现有优先级](<../src/client-subagents.ts#L62-L72>)是 title、displayTitle/label、短 id。真实 controller 改名可传到隔离组件，但不能证明截图中那行必然是正确持久 title。
- 区分“能力未提供”和“依赖/读取失败”，不把所有异常都归咎宿主缺能力，不因此扩大生产遥测或暴露私密地址。

## 6. 建议讨论次序

1. 摘要需求直接接收；是否采用灰色核对直达与独立设置兜底？
2. 无人值守选 B（agent 自动显式记下采用，无额外人工确认），还是 C（本次提交后端即采用）？
3. 默认是否按当前主会话及受权后代、明确到期、仅新项、按策略选择不冒人工答复、保留未兑现承诺？到期时长/时刻由开启时明确。
