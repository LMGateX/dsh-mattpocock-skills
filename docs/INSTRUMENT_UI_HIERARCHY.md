## 2. 已认可的裁决阅读契约

### 2.1 从字段堆叠改为逐项阅读

当前源码[就地裁决详情](<../src/client.ts#L660-L680>)连续渲染问题、工作流/事项长 ID、关联票、背景、建议、影响、结果、选项与作者引用；只有技术原文折叠。需要先解决内容组织，再配色。

| 层级 | 内容 | 默认呈现 |
|---|---|---|
| 区域标题栏 | 类别、数量、简短只读说明、关闭操作 | 同一紧凑操作条；说明不重复占大段高度 |
| 事项摘要 | 原问题预览、时间、状态、工作流可读名称 | 每项独立，明确分隔；打开类别先见事项清单 |
| 裁决核心 | 完整问题、已有选项、建议、影响 | 用户逐项展开；不塞进技术 JSON |
| 补充资料 | 长背景、长结果、来源/引用、标识、技术数据 | 分组折叠；存在才显示，不创建空壳 |

- 优先采用已验证公共原生 DisclosureRow；必要时用语义化 details/summary。标题/正文不能被固定单行控件截断后失去完整可达入口。
- 关闭用原生 Button，与标题同行或同一操作组，不再靠默认 h3/p/button 的大间距组合。
- 标题预览不自动生成另一份业务判断；展开可读、可复制完整原问题，不改写其含义。
- 工作流先显示可读 title，完整 workflowId/decisionId 放标识与来源；缺标题时保留真实 ID 作回退。关联票单独展示。
- 选项是裁决核心，不与技术日志一起隐藏。默认不替用户选中、自动保存或生成答复。
- 长诊断/日志按其已有字段折叠，不凭关键词删除、重写或把内容重新分类为错误。
- 首屏不铺开所有事项的全部正文，也不把每个字段套一层大卡片。

### 2.2 原生主题与颜色

复用 DSH 的实际公共 UI exports 与 --dsw-* token，不照抄私有宿主组件实现，不新增全局 CSS、私有 UI 库、导航框架或彩色大卡片/胶囊。最低受支持宿主的公共声明与当前宿主分别验证，不猜测控件或新版本 props。

- 待你裁决：红系、小面积强调，表示用户关注而非系统故障。
- 待落实（若继续沿用现有投影）：琥珀系，与待用户回答明确区分；不由 awaiting=true 宣称“已经用户裁决”。
- 问题为主题主文字与适当字重；时间/工作流/说明为可读的次级文字。
- 背景/来源/技术区用中性主题底色、分隔线与留白，不靠低对比灰字隐藏信息。
- T 蓝、S 青紫、差额中性正文色与未知/零值区分沿用原契约。颜色不能成为唯一语义。

### 2.3 创建时间必须可信

每个裁决项摘要应有明确的创建/首次登记时间位置；可另列最近业务更新时间。时间来源与格式化必须统一，而不是各个入口猜日期。

当前 [DecisionRecord 与 Change](<../src/controls/instrument-state.ts#L75-L78>)没有独立 createdAt/updatedAt；只有历史版本 recordedAt。不得直接把 history[0] 或当前版本时间称为创建时间：源历史清理可删除首版，assigned 历史也可能是授权子集。

1. 优先核验持久首次 put-decision 的事件/技术回执；只在当前授权读取路径能证明首次登记时提供创建时间。内部 dedup 可有目标与时间，但不是既有公开 UI snapshot 的直接字段，不能假定客户端已能读取。
2. 不能证明时明确“创建时间未知”；若展示最早保留版本，必须标为“最早保留记录”，不冒称创建。
3. 最近更新时间取当前业务版本；read/hidden、普通刷新、operationId 重放不应制造新的业务更新时间。
4. 使用浏览器时区与清楚可辨的绝对日期时间；可辅以相对时间，但不能只剩易误解的“刚刚”。完整时间和时区对键盘/触屏也应可达，不只靠 hover。
5. 新增只读时间投影、持久字段或兼容策略需在实施前明确最小契约及授权/清理/性能回归；本 UI 文档不默许改存储或公开 wire。用户要求时间展示已纳入目标，不能以新增接口未定而永久略过。

### 2.4 阅读与答复并存

保留[持久阅读契约](<DECISION_INTERACTION_AND_SETTINGS.md#4-阅读详情必须能与原生输入并存>)：输入、失焦、复制、普通刷新、新事项加入、归零或事项移出原类别，不抢焦点、不重置已展开事项、不突然挤掉阅读；分类变化显示已更新。按当前授权投影取内容，不缓存撤权正文。

Session/实例/调用者/授权范围切换即时隔离旧内容，unknown 不伪装当前。就地查看不写已读、hidden 或业务状态，不触发模型或自动打开侧栏。侧栏显式编辑保留原始业务修订草稿 CAS、冲突与错误保留草稿规则。

## 3. 全域审查范围与事实等级

用户要求“其他地方也查查”授权的是扩大研究，不等于其他区域所有候选均已获实现许可。审查至少覆盖：

- 输入区常驻摘要、工作流进度与 T/S 就地详情；
- 顶部协作入口与会话列表装饰；
- 右侧票进度、裁决列表/编辑器、窗口、工作树绑定/观测、能力与健康；
- 主动历史查询、交付监督与授权操作；
- 设置页会话查看、已优化设置页与本浏览器提醒；
- 工具来源卡、页面内通知和显式阅读入口。

报告区分三类证据：源码已确认的结构/文案问题；必须真实浏览器验证的视觉/键盘风险；已有可复用的良好模式。源码和元素树不能证明当前 GUI 像素或屏幕阅读器实际表现。以下矩阵是 2026-11-07 的只读源码审查，不是当前 GUI 的视觉缺陷清单或修复验收。本轮未确认阻断级 P0/P1；P2 为优先可读性/语义/可达性债务，P3 为后续一致性与抛光。

## 5. 验收矩阵

- 多事项与长内容：2 项用户问题和 88 项混合记录的合成 fixture；类别入口不等于展开所有正文，逐项完整内容可达，长 ID 无横向溢出。不复制真实私密业务正文进公开 fixture。
