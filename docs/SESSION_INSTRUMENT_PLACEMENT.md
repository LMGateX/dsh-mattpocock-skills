## 1. 推荐方向：常驻摘要、按需详情、对话留痕

不要把四个仪器做成四张常驻大卡片，也不要把所有状态只写进对话。推荐三层分工：

1. **Session 非滚动区域中的紧凑摘要**：用户读历史消息或侧栏关闭时，仍能知道当前任务状态和待裁决。优先 session header 的紧凑原生贡献；现有席位是内联 utility/action，不是完整第二行。完整独立状态条是可选宿主 seam 提议，不能宣传为当前插件已有能力。
2. **主动打开的 session 详情视图**：票清单、裁决问题/选项、执行租约与工作树关联等长内容。桌面优先复用右侧面板的独立“协作”入口/标签，不替换文件/Git 标签；能否同时显示取决于可用分栏和宽度，不能保证。只在用户点击时打开/切换内容。
3. **对话中的来源卡片/链接**：保留问题提出和结果讨论的上下文；当前未解决清单以账本为准，不用滚动找消息来恢复状态。

顶部还是输入区附近是布局取舍，不是两套业务状态。两处若都出现入口，也必须读取同一实例、同一已提交投影，只有一个主要摘要，避免重复计数与视觉噪声。

## 1.1 显示方式开关（已接受显示规格）

插件配置页提供显示位置/方式开关，独立于仪器功能启停：顶部紧凑摘要/提醒、输入框上方摘要、右侧详情入口、左侧 session 提醒，以及插件自己的对话来源卡片/链接展示。具体字段待定，位置默认组合见下方已认可方向。

- 沿用全局默认＋工作区稀疏覆盖，各显示字段支持继承/显式开/显式关；独立主 session 读取策略，但其状态不共享。首版不额外引入 session 级持久配置覆盖，临时展开/收起仅为实例对应的 UI 偏好。
- 位置开关可以组合，不把 header/input 的选择做成唯一互斥模式；同时开启时避免复制整套摘要，可让顶部负责紧凑提醒、输入区负责较丰富进度。右侧“开启”只是允许用户打开，不是启动时或状态更新时自动打开。
- 显示关闭不关闭账本、程序观测、主代理自动状态消费或已登记的义务；不清空票、裁决、租约、资源，也不伪装成状态为 0。对话显示开关只控制插件附加呈现，不隐藏原生业务消息/结果或删除历史。
- 用户可以隐藏所有常驻入口，但保存时解释后果：待裁决事项不再有持续可见的 GUI 提醒。提示不阻止用户明确选择，也不偷偷重开入口。没有开启任何详情位置时，不显示无效的“打开右侧详情”动作；替代入口需明确设计。
- 完整顶部第二行因缺宿主 seam 不作为可用开关；未来可做能力探测项，并显示 unsupported/原因，不能勾选后声称已有实现。
- 已认可的启用仪器后显示默认方向：顶部入口开、右侧详情允许开但默认收起；输入区丰富摘要与 session 列表徽标默认关；来源留痕保留。它不启用自动管理，也不是当前已运行配置；具体 schema/窄屏表现另行实现验证。

## 2. 候选位置比较

| 位置 | 适合 | 主要问题 | 推荐角色 |
|---|---|---|---|
| Session header | 持续总览、session 身份对应、阅读历史时查看当前状态 | 已有标题/目录/工具；现有内联席位空间有限，没有完整第二行席位 | 首选常驻入口：先做紧凑插件贡献；完整独立摘要行需要另议宿主 seam |
| Composer 上方/附近 | 需要用户回答的事项入口、下一步动作 | 与输入、附件、模型、执行状态争空间；输入模式/焦点可能变化 | 裁决的上下文操作入口或摘要备选，不铺开长票表 |
| 右侧 panel | 票表、裁决详情、执行与资源关联 | 可隐藏且已有文件/Git；仅放这里会失去持续可见性 | 主动打开的详情，不自动展开/抢占文件 |
| 对话时间线 | 事件来源、提出/回答的历史 | 长时间执行和历史阅读会淹没当前待办；旧快照易被当现状 | 辅助留痕和定位，不作唯一状态显示 |
| 左侧 session 列表 | 离开当前 session 后看到哪个任务需要注意 | 面积小、列表虚拟化/移动端可隐藏；不能容纳多个状态 | 可选的待用户裁决/重要异常徽标，不替代 session 摘要 |

## 3. 摘要中放什么

摘要按用户动作和任务内容组织，不按固定业务状态枚举组织。

| 仪器 | 常驻摘要 | 展开详情 |
|---|---|---|
| Tickets 进度 | 总票数＋当前任务声明的重点状态名称/计数；更多状态可展开 | 全部声明状态、含义、票清单与来源；保留部分完成等任意状态 |
| 待裁决 | 明确文字“待你裁决 N”，需要时注明关联阻塞数量；已裁决待落实单列 | 问题/背景、选项、建议、影响范围、来源与裁决/落实记录 |
| 双窗口 | 明确 T/S 或可读名称的 used/capacity；显示适用性/未知或超限原因 | 处理中票占位、预留/运行/停止执行、空位与当前策略来源 |
| Worktree 生命周期 | 资源数量及值得处理的提醒；健康情况下低视觉权重 | 执行/工作流/资源三个轴、owner/borrowed、关联 child、可退休原因/拒绝原因 |

- 待用户裁决有持久、可点击、可读的入口；不以普通未读圆点代替。
- 普通票进度与满窗口不是天然故障，不能全部显示红色；未知/失效/清理失败等事实另有显式健康标识。
- 自定义状态过多时按任务声明的展示优先级选择紧凑摘要；未声明优先级时按稳定字典顺序，不由 UI 猜测业务重要性。其他状态明确可展开，保留原名称/语义，不挤回“进行中/完成”等通用桶。跨 workflow 不合并同名但不同定义的状态；必要时只汇总票总数并按 workflow 展开。
- 票列表可以筛选当前 workflow，但待用户裁决/已裁决待落实提醒保留 owner 实例范围，避免旧任务义务消失；T/S 也注明实例范围，不拿筛选后的子集冒充空位。
- 摘要容器宽度/高度有上限，长名称可提供可访问的完整文本；详细视图完整展示，避免计数变化使布局反复跳动。具体像素、条目数与断点待视觉/视口验证。
- 当前快照与历史消息明确区分；鼠标/键盘可查看统计范围与更新时间，陈旧数据不当当前事实。

## 4. 详情视图与裁决交互

建议一个“协作”详情入口容纳四个 section/tab，而不是四个独立侧栏：票进度、待裁决、执行窗口、工作树。

- 从某个摘要点击时直达对应部分；从待裁决计数进入未解决列表，再选择具体问题。
- 用户主动展开或选择事项可以改变焦点；背景状态更新只刷新数据，不自动弹窗、切换 tab 或抢输入焦点。
- 用户裁决后展示“已裁决、待落实”，agent 真正落实后记录结果；已读、隐藏或关面板不关闭事项。
- 普通状态批量合并更新；新用户事项可有一次温和提醒，持久入口继续承担未解决状态。避免每次 heartbeat 都 toast 或播报。
- 不强制只通过按钮回答；模型按任务约定理解用户自然语言，并可更新事项、记录来源。仪器不追加自己的确认/审批层，也不把模型记录伪装成直接用户点击；宿主权限不因事项更新而改变。
- 详情选择、滚动和搜索在该 session 实例内保留是插件交互建议；宿主已持久化的仅是本浏览器按 session 键的右栏布局/地址，不是这些业务选择或任务账本。session 切换先核验归属，A 的迟到更新不能显示成 B 的裁决或执行。

## 5. 窄屏和子 session

窄屏下保留一个“协作”入口与待你裁决计数，再按空间提供进度/执行摘要；完整自由状态列表进入用户主动打开的详情。不能为了适配窄屏把状态词汇固定化。

安装版右栏在小于 768px 的 viewport 使用 fullscreen 模式，中间宽度也可能因剩余空间不足而收起。小屏详情应主动打开、明确返回，不假设它能与聊天持续并排；本轮只核验源码分支，没有测量真实手机/缩放视口。无论怎样展开，正确管理焦点。

受管 child session 展示主 session 归属和 assignment 范围，可跳回完整实例；不凭 child 页可见数据生成新容量或冒充整个任务的进度。

## 6. 宿主可行性与结论边界

安装版 公开 conversation 席位（SDK 包相对定位：`@deepseek-ai/dsh-client-ui-conversation/lib/types/client/contract/slots.d.ts`）提供 session-scoped 的 conversation.session.header.actions / utilities 两个 list 席位，适合紧凑摘要/入口；整个 header、lineage、corner 是 single 席位，不能为仪器接管。完整第二行状态条仍是缺失的宿主 seam。

安装版 输入区席位（SDK 包相对定位：`@deepseek-ai/dsh-client-ui-conversation/lib/types/client/contract/slots.d.ts`）提供 conversation.input.dock（输入卡片上方全宽 list，owner=InputZone）和 conversation.composer.dock（卡片下方 ambient list）。若希望纯插件版本同时显示更多任务自定义状态，input.dock 可作为主要摘要的备选：顶部只保留紧凑待裁决/协作入口，较丰富的单条摘要放输入框上方；这是已存在的候选席位，不必新加 header 横栏。但它位于 transcript 的同一个 bottom-sticky stack，会随 resident composer takeover/settling 等状态隐藏，需验证输入模式/窄屏高度，不能作为待裁决唯一提醒。composer.dock 已有上下文计量等内容，优先保持低密度。

这几种席位都不等于任意 DOM 插入权限；conversation.composer 本身是 chain 替换口，input.activity 是 single，均不应为状态仪器接管。读取 selected session 的可信 scope 再解析 owner 实例，不把展示入口当新的业务实例。安装版 header 的 actions/utilities 在 sessionless/blank hero 的 hideChrome 下不会呈现；fullscreen 右栏也可能遮住 header，因而“持续可见”是正常 session 视图中的位置目标，不是所有模式下已验证的保证。详见 [宿主边界与占位（本地原始记录不公开；参见验证范围）](<VERIFICATION.md#historical-evidence>)。

右面板可承载详情也不等于 plugin 有现成账本 Remote feed；数据订阅、权限、实例解析和状态健康仍须本插件实现。原生 openTab 会选中并展开面板，没有 background/no-focus 选项，因此普通状态刷新只更新投影，不调用 openTab。preferNewPane 是空间允许时的偏好，不是与文件/Git 共显保证；原生本地布局存储也不是跨设备/持久业务账本。不能通过 DOM 改写、占用其他插件的独占/chain 席位或 fork 整个 conversation 绕过缺失位置。

总体分工与配置页显示开关获 owner 认可。显示默认组合、首版仅位置开关和 workflow 分组方向已获 owner 认可；裁决/交付/暂停/取消的判断明确属于 Skills、用户/agent 约定、文档与模型，不再列为本插件待制定的业务规则。仪器提供记录/更新/呈现，模型认为需要时登记事项，不自动从 blocker/失败制造审批。业务票更新可以显式改 T，程序执行/S 仍由回执驱动。完整 secondary header seam 暂不作为纯插件第一版前提。像素稿、真实页面/窄屏测量和无模型客户端验证须另行安排；本报告不授予 live GUI 或运行时修改权限。
