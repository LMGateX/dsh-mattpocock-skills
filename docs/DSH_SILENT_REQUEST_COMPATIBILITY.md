# DSH compatibility: revalidate assembled model requests before handoff

**Target:** [DSH 0.2.3-alpha.2](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.2.3-alpha.2). **Release readiness on this target: failed.** This is an upstream-facing request-boundary reproduction and proposed contract, not a description of an available SDK feature. The plugin policy is defined separately in the [workspace silent-mode contract](WORKSPACE_SILENT_MODE.md).

## Reproduce offline

From this source checkout, with its development dependencies and the Node version declared by the bundle already available:

```sh
DSH_CONTROLS_HOST_ROOT=/absolute/path/to/installed/@deepseek-ai/dsh \
  node scripts/verify-silent-request-readiness.mjs
```

Use the directory containing the **installed CLI package manifest**, not the executable, a profile, or its package list. The [gate](../scripts/verify-silent-request-readiness.mjs) checks `engines.dsh` against that exact CLI and the relevant SDK packages it resolves, requires a real CLI entry, forces strict assertions and rejects missing tests, skips, todos and cancellations. It uses real installed SDK modules, disposable in-memory sessions/controls, and an inert adapter. It neither starts DSH nor uses credentials, a profile, or network calls.

[Conversation probe](../tests/workspace-silent-host.test.mjs), separately for Native and PTC:

1. Start a turn with collaboration ON to establish the ordinary conversation, plugin snapshot, and tool declarations (`tools` for Native; `tools:sdk` for PTC).
2. Start a second turn. A downstream `llm/stream` middleware captures the assembled request and pauses before calling the native continuation. Assert the request contains collaboration material and only the first turn reached the adapter.
3. Save OFF through the operator policy API, read back effective OFF for this session, and release the barrier. At the real `LlmRuntime` adapter handoff, require no owned declarations, tool history or snapshot. Require the turn, ordinary dialogue, unrelated context and tools to survive. Require the following, newly admitted request to be silent too and earlier raw session records to be unchanged.

**Observed on alpha.2:** exit 1: 9 passed, 3 failed, 0 skipped/todo/cancelled. Only the held Native, PTC and auxiliary compaction handoffs fail. Native receives the seven fixture collaboration declarations (both projected `tools` and `toolHistory`) and the old snapshot; PTC receives the stale generated SDK declarations and snapshot. Fresh OFF requests and stale execution-effect denial pass. The non-strict source test expects the held alpha.2 diagnostic and can pass; it is not release evidence.

[Compaction acceptance](../tests/silent-compaction-input.test.mjs) passes on alpha.2 with this bundle's narrow projection. It covers the mounted Host's verified-session/purpose check, and independently the real native `compactRegion`→`llm/stream`→adapter path with the same projector: attributed replay and tool changes are removed, unrelated inputs and old records survive, and downstream middleware, usage, cancellation and native recovery still work. The [unfiltered compaction baseline](../tests/silent-compaction-known-limitation.test.mjs) is deliberately **not** part of the gate. These passing compaction cases start with the projection already applicable; they do not test OFF saved in the middle of downstream compaction middleware or promise final compaction admission.

The [auxiliary compaction handoff probe](../tests/silent-compaction-final-handoff.test.mjs) is required in the gate: alpha.2's real `LlmRuntime` hands the inert adapter the old tool declaration, history and snapshot when OFF is verified during a downstream pause, whereas a fresh OFF request strips them. This probe uses a `purpose: compaction` request on the real mounted Host and dispatch path; it does not retest native region selection.

## Why the public hooks are insufficient

Pinned DSH source on `dsh-v0.2.3-alpha.2` (paths and symbols also present in the installed packages):

- [AgentLoop admission and retained tool set](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.3-alpha.2/packages/core/agent-loop/src/agent.ts#L286-L319): resolves the tool set and assembles the prompt before `agent/pre-step`; keeps that tool set. [Request preparation and streaming](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.3-alpha.2/packages/core/agent-loop/src/agent.ts#L430-L482) happen later. [Request building and logging](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.3-alpha.2/packages/core/agent-loop/src/agent.ts#L645-L734) append the native request header/updates and freeze the request. [Tool dispatch](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.3-alpha.2/packages/core/agent-loop/src/agent.ts#L575-L589) still uses the admitted set. [The deprecated `agent/request` hook](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.3-alpha.2/packages/core/agent/src/runtime-types.ts#L352-L374) can return call controls, not a replaceable admission bundle.
- [PTC's `tools:sdk` section](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.3-alpha.2/packages/core/tool-executor-ptc/src/index.ts#L24-L53) is rendered from the resolved tools but is not itself a transport tool schema. Removing native names alone leaves PTC declarations behind; removing `run_code` would incorrectly disable the unrelated nested tools too.
- [`llm/stream` waterfall](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.3-alpha.2/packages/llm/llm/src/index.ts#L1156-L1165) takes `next()` with no replacement input; the terminal closure captures `options`. [Actual dispatch](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.3-alpha.2/packages/llm/llm/src/index.ts#L1050-L1106) later projects the tools for the adapter and invokes its stream. An earlier listener cannot make a fenced final check on the terminal continuation, and cannot replace the frozen AgentLoop object.
- [Pressure compaction](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.3-alpha.2/packages/compaction/compaction-basic/src/index.ts#L172-L218) can run inside `agent/pre-step` or `agent/request`, before a new conversation request header is committed. [The native summarizer](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.3-alpha.2/packages/compaction/compaction-basic/src/summarizer.ts#L124-L163) supplies historical tools and messages in an independent `purpose: 'compaction'` request with its session ID and cancellation signal. The mutable alpha.2 auxiliary envelope makes narrow local projection possible; it is not a general replace/revalidate API.

## Requested public contract

Provide **host-owned final admission** before model adapter handoff, after any asynchronous preparation and middleware waits. It must apply to each ordinary attempt (Native and PTC) and each session-associated compaction attempt, including recovery/retry. A plugin must be able to register a revalidation decision using the trusted session/Agent scope, request purpose and attempt identity, with the existing signal. The callback may await the effective policy, but the host must fence the result against policy changes up to handoff (for example by a revision/lease invalidation contract); simply adding an earlier asynchronous notification leaves the same race. A request already handed to the adapter cannot be recalled by this contract; the probe does not inspect external transport bytes.

On invalidation, either admit a host-rebuilt attempt from the current scope or use a supported replace/project result that is applied at the terminal boundary. The host must keep all views of that attempt consistent: resolved executable set, direct schemas and historical tool updates, PTC nested SDK section, plugin-attributed prompt/context, and native request/attempt records. Keep just enough structural provenance for removal of owned sections and declarations; do not search or redact ordinary chat by text. If a conversation admission is rebuilt, dispose the old resolved set, preserve user input, and avoid duplicate sends, assistant output, tool effects or accounting. Re-check plugin-owned execution effects independently (stale call denial does not fix prior model exposure).

For compaction, use the same saved permission and trusted source identity to project only this plugin's retained material. Preserve protected prompt sections, other tools, ordinary user/assistant content, the original append-only records, route and model controls, the original signal, middleware chain, usage, native summary/recovery and retry semantics. Do not cancel unrelated turns, disable or replace compaction, mutate frozen requests, rewrite historical headers, or forge native request/usage records. The offline gate covers the cases above; broader release checks (including cold Skills discovery and cache invalidation, package verification, and current GUI activation) remain separate.
