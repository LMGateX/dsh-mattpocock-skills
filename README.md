## 0.16.0 task references and stable context

The default collaboration path points to the project’s existing task source instead of maintaining another business lifecycle. `put-task-reference` stores a narrow local handle, an authored source identity, a navigation locator and an optional label—no copied task body, status dictionary or completion state. T, assignment and decision associations accept that handle or an existing legacy ticket. T is a local selection of work, not the tracker’s unique-task or in-progress total. Native dispatch and questions remain primary.

References have their own bounded query/history kind, read-only native presentation and explicit capability. Source identity is an author report, not proof of external access, freshness or completion; this release adds no runtime fetching or background synchronization. Effective delegated scopes follow the actual parent chain, so narrowing an ancestor immediately restricts descendants and invalidates old scoped locators. Re-expansion may restore the intersection with a retained grant; this is not permanent cascading revocation.

Within the existing owned snapshot, stable guidance precedes changing notices and the current JSON. Notice-only changes are delivered, including clearing pending releases; missing baselines still restore the complete snapshot. Refresh TTL uses a monotonic elapsed clock while persisted event times remain program-owned wall time. Optional supervision no longer prescribes creating an extra subagent task. Legacy resource/history tools and opt-in delegate remain compatible.

Instrument storage reads V1/V2 and first writes a reference through an atomic V3 upgrade; old binaries cannot read V3 and must not be allowed to downgrade-write it. Existing tickets, original authors, explicit decision flags and history remain readable under current authorization. No production records are automatically migrated or cleared. See [migration and rollback limits](<MIGRATION.md>), [the guide](<CONTROLS.md>) and [verification](<docs/VERIFICATION.md>). This release does **not** install or activate the existing local Profile, modify the shared SDK or restart the service.

## 0.13.0 native-only cwd (breaking)

If you manually applied the old `host-patches/` files or used the old CLI, restore the original SDK from your own backup before upgrading; this repository no longer contains that tooling. ## Usage sequence and known limitations

1. **Installation and activation belong to DSH.** This package supplies a native Skill provider and declares `stable` and `beta`, with `stable` as the default. Installation does not automatically change the owner profile or project conventions.
2. **Project setup is separate.** In a target project session with the plugin enabled, run `/setup-matt-pocock-skills` before first using the engineering workflows. It confirms the tracker, labels, and domain documentation with the user and writes project configuration; it is not the plugin installer. GitHub/GitLab workflows need the appropriate CLI, authentication, and authorization; local Markdown is also supported.
3. **Use native invocation.** Users may invoke `/skill-name`; agents obtain bodies through the DSH `skill` tool, including upstream user-only bodies in this adapter. Subsequent Skill references are not recursively executed slash text. Source user-only remains a user-led usage hint, not a body-access ban; loading neither mandates a full workflow nor expands action permissions. Explicit false/false source entries would remain disabled.

Compatibility notes for the currently inspected local DSH implementation (not a claim that every profile enables these capabilities):

- `/compact` accepts no arguments. Upstream examples of `/compact <instructions>` cannot be used verbatim. A same-name `/clear` entry remains unverified; do not automatically clear a session.
- DSH recognizes both `AGENTS.md` and `CLAUDE.md` by default; blanket filename substitutions are unnecessary.
- **Background dispatch does not guarantee headless lifetime.** The inspected headless driver summarizes and exits after the root becomes idle; continued normal completion and delivery of background work are not guaranteed. This does not establish equivalent Web behavior. Full unattended workflows require a separate host-lifecycle decision.
- Git/worktrees, browsers, online research, and shared notes depend on target environment capabilities and permissions. The provider does not install those tools, authorize external writes, or bypass filesystem policy.
- **Host versions.** The Skills provider was verified against DSH `0.1.2-rc.1`, `0.1.7-alpha.2`, `0.1.7-rc.2`, `0.2.0-rc.1`, `0.2.0-rc.2`, and `0.2.1-alpha.1`, and needed no runtime adaptation for that surface before the deliberate 0.17.0 advisory-access change. `0.2.1-alpha.2` was the first host that required an adaptation (the native subagent activation seam). `0.2.1-alpha.3` removed `connection.operator` in favour of the owner `connection.browserPeer`; the optional controls plane read the old property, so from alpha.3 on it aborted its mount before registering its nine tools while Skills delivery stayed intact (cordis drops `warn` at its default level, so the live terminal showed nothing). The operator Peer is now read version-neutrally (`connection.operator ?? connection.browserPeer`, failing closed when neither exists), with both spellings covered by tests. `0.2.1-alpha.4` changed how the install-time gate reads a plugin: a declared `engines.dsh` decides alone, and the `@deepseek-ai/dsh*` peers are only the fallback. 0.13.0 declares `"engines.dsh": "~0.2.1-alpha.2"`, so the engine-aware gate admits `0.2.1-alpha.2`, `0.2.1-alpha.3` and the `0.2.2-alpha.*` line while refusing `0.2.1-alpha.1`, `0.2.0-rc.2` and `0.3.0-alpha.1`; the old compatibility bridge and its next-boot request no longer exist. `0.2.2-alpha.2` required a runtime adaptation while `mattpocock_execute` existed: tool execution moved into executor plugins and the old single-call `ctx.tools.execute` was removed, so the wrapper used the public `ToolExecutionPipeline` on that host line. The 0.7.0 source line removes that wrapper and its `executeNative` path entirely; ordinary dispatch is native. The Skills provider itself is unchanged. DSH `0.2.2-alpha.3` was rechecked on 2026-11-04 with no plugin code, metadata or artifact change: its type set compiled the root and Client builds with zero errors, the full suite reported **1077 passed and 0 failed** (9 environment-gated skips), and the published 0.10.0 artifact installed in an isolated headless profile exposing **27 Skills, 11 model-visible**. This is a headless compatibility check, not a browser or model run. See the [host compatibility record](docs/HOST_COMPATIBILITY.md) (Chinese).

**Design update (2026-11-04; 0.9.0 fact boundaries).** Native dispatch remains first for unbound lanes: ordinary children use native subagent creation; prepare a worktree only when task-defined write isolation requires it (read-only lanes may share a stable checkout). `mattpocock_delegate` retains binding-first creation but is **not registered by default**; only a profile with `delegate: true` opts in. It reports creation, binding and assignment separately, and an accepted or uncertain operation is never replaced by a second native child. The execution fact previously called `initialCwd` is stored as `headerCwd`, a source value that does not prove the effective initial directory; legacy `initialCwd` rows are read compatibly. Native execution associations are inferred where appropriate, late published ends are handled without a live Agent, and no initial-cwd path-equality association is produced. `mattpocock_execute` remains removed and there is no new model tool, Remote method or storage domain. Installation/activation is still a separate gate and no local DSH/Profile/GUI was installed; see [the fact-boundary design](docs/INSTRUMENT_FACT_BOUNDARIES.md) and [verification](docs/VERIFICATION.md).

**Fact-boundary follow-up (2026-11-04; 0.9.0 source).** The [fact-boundary and recovery design](<docs/INSTRUMENT_FACT_BOUNDARIES.md>) now has a matching source implementation and new acceptance tests: header-cwd claims are narrowed, creation/binding/assignment outcomes are separated, late lifecycle events are handled with run fencing, provenance is explicit per field, and default guidance is conditional. Historical release results still describe their own versions; source tests and fixtures are not an installation or GUI proof.

Overage or incomplete T/S observation does not veto valid native delegation or add business approval. Agents manage Git themselves: cleaned trees leave continuous injection, discarded-but-uncleaned trees remain reminders, and history has no default TTL.

The 0.4.2–0.12.x bridge workflow is historical. 0.13.0 removes that provider, the page-level next-boot request and the old CLI.
