# Repository Instructions

Before implementing or reviewing this repository, read `docs/DESIGN.md` and `docs/IMPLEMENTATION_PLAN.md`.

The accepted decisions in `docs/DESIGN.md` are authoritative. In particular, do not rewrite vendored Skill bodies, add runtime fetching, change channel semantics, or alter provider precedence without explicit user approval and a matching design-document update.

For DSH/worktree compatibility, read [the worktree research](docs/WORKTREE_ISOLATION.md); for multi-round subagents, initial workspace binding or cleanup, also read [the continuable-workspace study](docs/CONTINUABLE_WORKSPACES.md). For plugin policy or lifecycle/window instrumentation, read [workspace controls](docs/WORKSPACE_WORKFLOW_CONTROLS.md); for session isolation, ticket progress or pending decisions, read [session instruments](docs/SESSION_INSTRUMENTS.md) and [domain terms](GLOSSARY.md). Business judgments belong to Skills/user agreements/model, not instrument approval gates; execution signals remain program-only. For controls implementation, read [the core interface and verification contract](docs/CONTROLS_CORE.md); For business instrument records or shared CAS changes, also read [the second-stage contract](docs/INSTRUMENT_RECORDS.md); the early-stage records describe historical unmounted cores. For host authorization, notifications or actual consumption, read [host integration](docs/HOST_INTEGRATION.md), [runtime coordination](docs/RUNTIME_COORDINATION.md) and [consumption](docs/CONSUMPTION.md); for window/resource changes read [windows](docs/WINDOW_CORE.md) and [resources](docs/RESOURCE_CORE.md); for client seats or artifacts read [client integration](docs/CLIENT_INTEGRATION.md). Current delivered capabilities and host gaps are in [the shipped guide](CONTROLS.md).

Keep implementation-specific evaluation outside vendored upstream Skill directories. Verify generated artifacts and the packed installable bundle before claiming completion.
